# Publishing to the Hermes plugin store

The plugin is **not in the store** — it is a local folder under
`$HERMES_HOME/plugins/pandora` (and `profiles/rob/plugins/pandora`). The store
lists entries from `plugin-catalog/*.yaml` in the Hermes repository; each entry
points at a **public GitHub repo pinned to a commit**, not at a local folder.

## What is already done

- `assets/icon.png` — 512×512 store icon (generated by `assets/generate_artwork.py`)
- `assets/hero.jpg` — 1774×887 README hero (user-supplied artwork)
- `assets/card.jpg` — 1200×600 (2:1) catalog card image, the entry's `image:`
- `LICENSE` — MIT (also `license: MIT` in `pandora/plugin.yaml`; the catalog
  schema itself has no license field)
- Store-facing description (below)
- Catalog entry template (below)

## What only you can do

1. **Publish the repo.** `~/pandora-plugin` is not a git repository and has no
   remote. Create a public repo (e.g. `hermes-pandora`) and push the `pandora/`
   tree plus `assets/`, `pyproject.toml`, `README.md` and `STORE.md`.
   Do **not** commit `.env`, `auth.json`, `bin/mpv.exe` (122 MB; point at the
   upstream build in the README) or `backups/`.
2. **Pin a commit.** `git rev-parse HEAD` → the 40-hex `sha` below.
3. **Add the catalog entry.** In the Hermes repo, copy the YAML below to
   `plugin-catalog/pandora.yaml`, replace `<owner>` and `<sha>`, and open a PR.
   A maintainer reviews it (tier, description accuracy, disclosures).
4. **Screenshot (optional but recommended).** Add `assets/menu.png` — a shot of
   the open menu with stations visible — and list it under `screenshots`.
   URLs must be on a GitHub host (`raw.githubusercontent.com` is accepted).

## Store message

Copy this block into the catalog PR description / store listing:

Your music. Your desktop. Your agents. All connected.

Pandora for Hermes brings your Pandora experience directly into Hermes Desktop. Fire up a favorite station, discover something new, and keep the music flowing while you work.

Everything is right where you need it. See the current song and artist in your status bar, then click the chip to control playback, skip tracks, rate songs, adjust volume, switch stations, browse recent stations, or change audio outputs. Search for an artist or song and instantly spin up a new station. If you have a Premium account, enjoy on demand playback and access to your playlists. You can even cast your music to compatible media devices on your network.

But this plugin goes beyond desktop playback. Its seven built-in agent tools let Hermes interact with Pandora directly through the CLI, making it just as useful for autonomous agents and headless environments as it is for everyday desktop listening.

Supports Pandora Free, Plus and Premium.

Powered by mpv for local playback. The plugin can automatically download a verified portable build, or you can install it yourself using `hermes pandora setup`.

Install from the plugin store (Capabilities → Plugins) or via the CLI (`hermes plugins install pandora`). Uninstall with the plugin's trash icon in Capabilities → Plugins (or `hermes plugins remove pandora`) — by design that keeps your saved login so a reinstall starts signed in. To also delete your Pandora credentials, the saved session and the downloaded mpv build, run the `full-wipe-pandora-plugin.ps1` script from this repository's `scripts/` folder.

## Disclosures to keep accurate

- **Terms of Use:** this plugin uses automated access to pandora.com that may
  violate Pandora's Terms of Use; use is at the user's own account risk. Put that
  sentence verbatim in the PR description as well as the README.
- **Trademarks:** PANDORA and related marks are trademarks or registered
  trademarks of Pandora Media, LLC. This plugin is independent and uses the name
  only to describe what it interoperates with; no Pandora logo or artwork is
  bundled.
- **Credentials:** the plugin logs into the user's own Pandora account with
  email + password (`hermes pandora login`). Credentials flow only through
  Hermes's secret scope: `pandora login` writes `PANDORA_EMAIL`/`PANDORA_PASSWORD`
  into the ACTIVE profile's `.env` (or the user's external secret source), and
  the code reads them via `agent.secret_scope.get_secret`. The session token
  plus the PerimeterX cookie jar live in the active profile's `auth.json`
  (`providers.pandora`, same convention as the official Spotify plugin). For
  all-profiles use, the two values can be placed in the managed env layer
  (`$HERMES_MANAGED_DIR/.env`) instead. The plugin keeps no credential store of
  its own and never reads another profile's files. No credentials are sent
  anywhere except pandora.com.
- **Terms of Service:** the plugin uses automated access to pandora.com (the web
  player's own endpoints) with the user's own account. Pandora's Terms of Use
  restrict access to its official applications and may permit account
  termination for third-party clients — disclose this plainly in the README and
  the catalog PR (rule 13), and use at your own account risk. Unofficial and
  unaffiliated.
- **Platforms:** only Windows has been exercised end to end. The player uses
  mpv (all platforms) and a Windows Job Object to kill mpv with Hermes (a
  no-op elsewhere), so list `windows` until macOS/Linux are tested.
- **Profile scoping:** Hermes mounts a user plugin's dashboard API per profile, so
  the app's **active profile** must have Pandora installed and enabled — a profile
  without it answers `404 {"detail":"Plugin not found"}` and the chip shows a
  "not available in this profile" note. The desktop half is app-level (one copy in
  `desktop-plugins/pandora/`). A store install lands in the active profile
  automatically; a CLI install goes to the launch profile unless `-p` is used.
- **Catalog rule 8:** `desktop/plugin.js` retries `window.hermesDesktop.api` when
  `ctx.rest` returns 404. `plugins validate` flags that fallback as a "raw bridge"
  under the SDK-surface-only rule; if a reviewer objects, delete `rest()`'s
  fallback and use `ctx.rest` alone.
- **Profile model:** credentials resolve per profile through Hermes's secret
  scope (`.env`, external secret source, or the managed env layer). Session
  state lives in each profile's `auth.json` and self-heals via automatic
  re-login — with the managed env set once, there is no per-profile login. The
  mpv binary remains shared in the launch home's plugin-data.
- **Catalog rule 9 (private core imports):** the session state is persisted in
  `auth.json` under `providers.pandora` via `hermes_cli.auth` (the same
  provider-state convention the official Spotify plugin uses; there is no
  public plugin API for a third-party session token, and rule 11 forbids a
  plugin-owned credential store). `plugins validate` flags the `hermes_cli.auth`
  imports; disclose them in the PR. Read/clear go through the public helpers
  (`get_provider_auth_state`, `clear_provider_auth`); the one write seam is
  `_provider_state_transaction` + `_save_provider_state_to_source`, which writes
  back to the store the state was read from and never touches
  `active_provider`.
- **mpv is not bundled (catalog rule 17).** The package carries no executables;
  `hermes pandora setup` (or the automatic first-play fetch) downloads the
  **official upstream build** — `mpv-player/mpv` release `v0.42.0`, asset
  `mpv-v0.42.0-x86_64-pc-windows-msvc.zip` — into
  `<launch home>/plugin-data/pandora/bin`. `DEFAULT_MPV_SHA256` pins the archive
  in code and is verified before extraction; `PANDORA_MPV_SHA256` overrides it and
  `PANDORA_MPV_URL` / `PANDORA_MPV_PATH` remain the escape hatches. The
  `github-release://owner/repo/tag/asset` form resolves the asset id through the
  GitHub API, because the browser `/releases/download/...` URL 504'd during
  testing while the API asset route served the file. mpv is GPLv2+ and the
  upstream zip ships no licence text, so `LICENSE-GPL-2.0.txt` and
  `NOTICE-third-party.txt` from `pandora/bin/` are copied beside the binary.
  Upstream mpv publishes Windows builds only as `libmpv` plus the CLI zip used
  here; there is no separate official installer.
- **Still shipping the old `bin/mpv.exe`?** Don't: the install scanner flags
  bundled executables as HIGH and blocks community installs without `--force`.

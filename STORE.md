# Publishing to the Hermes plugin store

The plugin is **not in the store** — it is a local folder under
`$HERMES_HOME/plugins/pandora` (and `profiles/rob/plugins/pandora`). The store
lists entries from `plugin-catalog/*.yaml` in the Hermes repository; each entry
points at a **public GitHub repo pinned to a commit**, not at a local folder.

## What is already done

- `assets/icon.png` — 512×512 store icon (generated by `assets/generate_artwork.py`)
- `assets/hero.png` — 1200×630 card/social image
- `LICENSE` — MIT (also `license: MIT` in `pandora/plugin.yaml`; the catalog
  schema itself has no license field)
- Store-facing description (below)
- Catalog entry template (below)

## What only you can do

1. **Publish the repo.** `~/pandora-plugin` is not a git repository and has no
   remote. Create a public repo (e.g. `hermes-pandora`) and push the `pandora/`
   tree plus `assets/`, `pyproject.toml`, `README.md` and `STORE.md`.
   Do **not** commit `.env`, `auth.json`, `bin/mpv.exe` (122 MB; point at the
   upstream build in the README) or `backups/`.
2. **Pin a commit.** `git rev-parse HEAD` → the 40-hex `sha` below.
3. **Add the catalog entry.** In the Hermes repo, copy the YAML below to
   `plugin-catalog/pandora.yaml`, replace `<owner>` and `<sha>`, and open a PR.
   A maintainer reviews it (tier, description accuracy, disclosures).
4. **Screenshot (optional but recommended).** Add `assets/menu.png` — a shot of
   the open menu with stations visible — and list it under `screenshots`.
   URLs must be on a GitHub host (`raw.githubusercontent.com` is accepted).

## Catalog entry (`plugin-catalog/pandora.yaml`)

```yaml
name: pandora
repo: https://github.com/36North/Pandora-for-Hermes
subdir: pandora
sha: <40-hex-commit — the pushed commit>
description: >-
  Pandora (pandora.com) inside Hermes: play your stations on this PC or a Cast
  device, see the current artist and song in the desktop status bar, and
  left-click it for play/pause, skips, thumbs, volume, recent stations and
  output. Search an artist or song to start a station. Works on Free and Plus;
  on-demand songs, albums and playlists appear only when the account's plan
  allows them. Also usable headless: the seven agent tools work from the CLI
  with no desktop app. Local playback uses mpv, which is not bundled: `hermes
  pandora setup` downloads a verified portable build, or the plugin fetches it on
  first playback.
maintainer: 36North
tier: community
category: tools
docs_url: https://github.com/36North/Pandora-for-Hermes#readme
version: "0.3.0"
title: Pandora
image: https://raw.githubusercontent.com/36North/Pandora-for-Hermes/<sha>/assets/icon.png
screenshots: []
readme: true
platforms:
  - windows
capabilities:
  provides_tools:
    - pandora_playback
    - pandora_search
    - pandora_stations
    - pandora_feedback
    - pandora_collection
    - pandora_playlists
    - pandora_devices
  provides_hooks: []
  provides_middleware: []
  requires_env: []
```

## Disclosures to keep accurate

- **Trademarks:** PANDORA and related marks are trademarks or registered
  trademarks of Pandora Media, LLC. This plugin is independent and uses the name
  only to describe what it interoperates with; no Pandora logo or artwork is
  bundled.
- **Credentials:** the plugin logs into the user's own Pandora account with
  email + password (`hermes pandora login`). On Windows the password is
  **DPAPI-encrypted** at `plugin-data/pandora/credentials.bin`; the email stays in
  the launch profile's `.env`, and the session token plus the PerimeterX cookie
  jar live in `auth.json`. DPAPI ties the ciphertext to the user account (no key
  file, unreadable by another user or on another PC). No credentials are sent
  anywhere except pandora.com.
- **Platforms:** only Windows has been exercised end to end. The player uses
  mpv (all platforms) and a Windows Job Object to kill mpv with Hermes (a
  no-op elsewhere), so list `windows` until macOS/Linux are tested.
- **Profile scoping:** Hermes mounts a user plugin's dashboard API per profile, so
  the app's **active profile** must have Pandora installed and enabled — a profile
  without it answers `404 {"detail":"Plugin not found"}` and the chip shows a
  "not available in this profile" note. The desktop half is app-level (one copy in
  `desktop-plugins/pandora/`). A store install lands in the active profile
  automatically; a CLI install goes to the launch profile unless `-p` is used.
- **Catalog rule 8:** `desktop/plugin.js` retries `window.hermesDesktop.api` when
  `ctx.rest` returns 404. `plugins validate` flags that fallback as a "raw bridge"
  under the SDK-surface-only rule; if a reviewer objects, delete `rest()`'s
  fallback and use `ctx.rest` alone.
- **Profile independence (account):** login, device id, DPAPI blob and the mpv
  binary are shared across profiles via `_account_home()`, so only the code and
  the `plugins.enabled` entry are per profile.
- **mpv is not bundled.** The package carries no executables; `hermes pandora
  setup` (or the automatic first-play fetch) downloads a portable build into
  `<launch home>/plugin-data/pandora/bin`, verifies the zip's SHA-256 (the
  sibling `.sha256` asset, or `PANDORA_MPV_SHA256`) and extracts it. Publish
  `vendor/mpv-portable.zip` + `vendor/mpv-portable.zip.sha256` as release assets
  under tag `mpv`. `DEFAULT_MPV_URL` uses the
  `github-release://<owner>/<repo>/<tag>/<asset>` form, which resolves the asset
  id through the GitHub API — the browser
  `/releases/download/...` URL 504'd during testing, while the API asset route
  served the full 49 MB. mpv is GPLv2+; keep its license/notice in the zip and
  in `bin/`.
- **Still shipping the old `bin/mpv.exe`?** Don't: the install scanner flags
  bundled executables as HIGH and blocks community installs without `--force`.
